## 2. 三个词的答案（对应 §2.1）

| 词 | 事实 | 你要写的 ★ |
|---|---|---|
| **SOP** | 源 = **协议 + 主机 + 端口**；执行者是**浏览器**；**只拦"读响应"，不拦"发请求"** | 用你自己的话串起来 |
| **XSS** | 让一段 JS 在**受害者信任的那个源里**执行 | ★ 别写"然后返回" —— 没有"返回"这个动作 |
| **DOM** | 浏览器把 HTML 文本**解析成内存里的一棵节点树**；JS 操作的是这棵树 | ★ 见 §11 |

**SOP 的三条硬事实（都有实验支撑，见 §10）：**
1. `http://127.0.0.1:8080` 和 `http://127.0.0.1:8081` **不同源**（端口）
2. `http://127.0.0.1:8080` 和 `http://localhost:8080` **不同源**（主机）
3. `a.example.com` 和 `b.example.com` **也不同源**（子域名算跨源）

## 3. 三份源码（对应 §2.2）

### （1）反射型 xss_r — 已贴在 README 里 ✅

```php
<?php

header ("X-XSS-Protection: 0");

// Is there any input?
if( array_key_exists( "name", $_GET ) && $_GET[ 'name' ] != NULL ) {
    // Feedback for end user
    echo '<pre>Hello ' . $_GET[ 'name' ] . '</pre>';
}

?>
```

**★ 两处要注意（这是 §2.3 的原料）：**
- `echo '<pre>Hello ' . $_GET['name'] . '</pre>';` ← **用户输入直接拼进 echo**
- `header ("X-XSS-Protection: 0");` ← DVWA **主动关掉**浏览器那个老式 XSS 审计器

### （2）存储型 xss_s — 已贴在 README 里 ✅

关键几行（你贴过的）：

```php
    $message = trim( $_POST[ 'mtxMessage' ] );
    $name    = trim( $_POST[ 'txtName' ] );

    // Sanitize message input
    $message = mysqli_real_escape_string($GLOBALS["___mysqli_ston"], $message);
    $name    = mysqli_real_escape_string($GLOBALS["___mysqli_ston"], $name);

    // Update database
    $query  = "INSERT INTO guestbook ( comment, name ) VALUES ( '$message', '$name' );";
```

**★★ 这里藏着一个极重要的点（§6 / §7.1 会用）：**

> 它调用了 `mysqli_real_escape_string()` —— **看起来"做了防护"，但那是对 SQL 有效的转义。**
> **它不把 `<` 变成 `&lt;`，所以对 XSS 一点用都没有。**
>
> **这就是"在错误的地方做了正确的防护"** —— 你在 §7.1 写"为什么过滤不算修"时，这是最有力的例子。

### （3）DOM 型 xss_d — 还空着 ⬜ **你要填**

**要粘两样：**

**① `view_source.php?id=xss_d&security=low` 给你的 PHP（它是空的！）：**

```php
<?php

# No protections, anything goes

?>
```

**② 页面里的内联 `<script>`（★ 真正的那段）—— 在 `<select name="default">` 里面：**

```html
<select name="default">
	<script>
		if (document.location.href.indexOf("default=") >= 0) {
			var lang = document.location.href.substring(document.location.href.indexOf("default=")+8);
			document.write("<option value='" + lang + "'>" + decodeURI(lang) + "</option>");
			document.write("<option value='' disabled='disabled'>----</option>");
		}

		document.write("<option value='English'>English</option>");
		document.write("<option value='French'>French</option>");
		document.write("<option value='Spanish'>Spanish</option>");
		document.write("<option value='German'>German</option>");
	</script>
</select>
```

**怎么拿到 ②**：`Ctrl+U`（查看网页源代码）→ `Ctrl+F` 搜 `document.write`

**那个 `+8` 不是魔法**：字符串 `default=` 正好 **8** 个字符。

## 8. §4 重点专题：payload 站在哪（全是推理，不用做实验）

**三步提问法**（这就是 §4 的骨架）：

```text
① 我的输入落在 HTML 的【什么状态】里？
② 在【这个状态】下，哪个字符有特殊含义？
③ 那个特殊含义够不够我干坏事？
```

| 类型 | ① 落点 | ② 有特殊含义的字符 | ③ 要逃吗 | 怎么逃 |
|---|---|---|---|---|
| 反射型 | **文本节点** | `<` | ❌ | — |
| 存储型 | **文本节点** | `<` | ❌ | — |
| **DOM 型** | **属性值** | **`'` 和 `>`** | ✅ | `'>` |

**三种解析器遇到"残缺输入"的行为（★ 结论你自己下）：**

| 解析器 | 行为 | 证据 |
|---|---|---|
| **HTML** | **容错** —— 会自己补全、跳过，继续解析 | 你写 `<script>` 时**不需要**注释掉后面的 HTML |
| **SQL** | **严格** —— 引号不配对就报错 | 你**必须**加 `#` 或 `-- ` |
| **JS** | **严格** —— 字符串不闭合就报错 | 所以 JS 上下文里才需要 `//` |

**属性逃逸的通用四步：**

```text
[关属性引号] [关当前标签] [开新标签] [写代码]
     '            >       <script>    alert(1)</script>
```

- 属性用**双引号**时：payload 起点改成 `">`
- 属性**没有引号**时：不需要关引号，直接从 `>` 或空格开始

## 9. 日志可见性（对应 §8.1）★ 台帐只给事实

### 三条已知结论

| 类型 | 提交方式 | payload 位置 | access.log 里看得见吗 |
|---|---|---|---|
| **反射型** | GET | URL 查询串 | ✅ **看得见** |
| **存储型** | POST | **请求体** | ❌ **看不见** |
| **DOM 型** | GET（或 fragment） | URL / **fragment** | ⚠️ **看情况**，见下 |

### `#` 的实测（2026-09-27 做的）

访问 `http://127.0.0.1:18099/normal?default=AAA#default=BBB`

**日志服务器只收到：**

```text
path = /normal?default=AAA
```

**`BBB` 凭空消失了。**

| 名词 | 含义 |
|---|---|
| `?` 后面 | **查询串（query string）** → **会发给服务器** |
| `#` 后面 | **片段（fragment）** → **浏览器自己用，从不发给服务器** |

### ★ 你要下的结论

- DOM 型的 payload 可以**完全不进服务器日志**，但漏洞**真实存在** → 这对"日志能不能做安全分析"意味着什么？
- 同时注意：DOM 型**连服务器完全没参与**都能算 XSS（PHP 是空的）

### 检测规则（§8.3）

**现有工具抓不到 XSS。** 已知事实：

- `[6]` 规则的条件是「query 里有 `%27` **且** 含 SQL 关键字」→ XSS payload 不满足
- **XSS payload 的特征候选**：`<script>` / `%3Cscript%3E` / `onerror=` / `onload=` / `alert(` / `javascript:`
- ⚠️ **上次的教训**：`SQLI_KEYWORDS` 写了大写却用 `.lower()` 比较 → 搜不到任何东西（假阴性）

## 10. SOP 实验的原始数据（备查，可能写进 §4 或附）

两个服务器：A = `127.0.0.1:18101`，B = `127.0.0.1:18102`

| 实验 | JS 看到的 | 服务器看到的 |
|---|---|---|
| 同源 `fetch('/data')` | `status=200` ✅ | `[A] 收到请求` |
| 跨端口 → B:18102 | `status=0` ❌ | **`[B] 收到请求，Origin=http://127.0.0.1:18101`** ✅ |
| 跨主机 `localhost` vs `127.0.0.1` | `status=0` ❌ | **`[A6] 收到请求`** ✅ |
| 跨源但 B 发了 `Access-Control-Allow-Origin: *` | `status=200` ✅ | `[B] 收到请求` |

**★ 关键事实：`status=0` 的意思是"浏览器拦下来了"，不是"服务器没响应"。**

> **`Origin` 头是浏览器自动加的**，服务器靠它知道"这个请求是哪个页面发起的"。
> **服务器本身不做任何同源检查** —— 拦截发生在浏览器里。

**DOM ≠ HTML 文本（实测）：**

| | 服务器发来的文本 | 现在内存里的 DOM |
|---|---|---|
| 同一行 | `<pre id="out" ...></pre>`（空） | `<pre id="out" ...>--- 开始 ---...`（350 字符） |
| 整页长度 | **1316** 字符 | **1681** 字符 |

## 11. DOM 的定义（对应 §2.1 那一格）

**DOM = Document Object Model = 文档对象模型**

| 词 | 意思 |
|---|---|
| **Document** | 文档 —— 那个 HTML 页面 |
| **Object** | 对象 —— 每个节点都是 JS 里的对象，有属性能读能写 |
| **Model** | 模型 —— 它是文档在内存里的一种表示 |

```text
服务器返回的 HTML 文本  →  浏览器解析  →  内存里的节点树(DOM)  →  JS 读写它
      （图纸）                              （房子）             （施工队）
```

**★ 这一格要你自己写，形状给你：**

```text
DOM = 浏览器把服务器发来的 HTML ____，解析成内存里的一棵 ____；
      JS 操作的是 ____ 。
      所以"页面最终的样子" ≠ ____   ← 这就是 DOM 型 XSS 的立足点
```

## 13. ★ 方法：什么叫"根因"，怎么找"原罪行"

### 13.1 "根因"不是什么

**❌ 不要写"没过滤特殊字符"** —— 那描述的是"**补丁缺失**"，不是**机制**。
而且"过滤"这个思路本身就是错的（黑名单永远漏，见 §7.1）。

### 13.2 根因只有一句话

> **系统在某个环节，把【用户输入】当成了【代码】而不是【数据】。**

命令注入 / SQL 注入 / XSS / 模板注入 / 反序列化 —— 全是这一句话的变体。

### 13.3 怎么找"原罪行"是哪一行 ★★★

> **原罪行 = 数据和代码【合体】的那一行，也就是"字符串拼接"那一行。**

**"取值"那一步是无罪的**（读进来的数据还是数据）：

| 模块 | 取值（无罪） | **合体（原罪）** |
|---|---|---|
| 命令注入 | `$target = $_REQUEST['ip'];` | `shell_exec('ping -c 4 ' . $target);` |
| SQL 注入 | `$id = $_REQUEST['id'];` | `"SELECT ... WHERE user_id = '$id';"` |
| 反射型 XSS | `$_GET['name']` | `echo '<pre>Hello ' . $_GET['name'] . '</pre>';` |
| 存储型 XSS | `$_POST['mtxMessage']` | `echo "...Message: {$message}...";`（形如：输出留言板时把变量插进 HTML） |
| DOM 型 XSS | `var lang = document.location.href.substring(...);` | `document.write("<option value='" + lang + "'>...");` |

**看到"取值"就放过它，看到"拼接"就停下来。**

### 13.4 写根因的时候，说清三件事

```text
① 谁把它当成了代码？   → 服务器（PHP）  还是  浏览器（JS）？
② 在哪一步？           → 存的时候 / 输出的时候 / 构造 DOM 的时候？
③ 缺了什么处理？       → 缺的是【与目标位置匹配的编码】
```

### 13.5 三种 XSS 的区别，只用问一个问题

> **那段 HTML 字符串，是在哪里被拼出来的？**

```text
payload 有没有被【服务器】拼进返回的 HTML？
├─ 有 ──→ 它从哪来？
│          ├─ 本次请求（URL / body）  ──→ 反射型
│          └─ 数据库（之前存进去的）  ──→ 存储型
└─ 没有 ─→ 那是谁拼的？──→ 浏览器里的 JS ──→ DOM 型
```
